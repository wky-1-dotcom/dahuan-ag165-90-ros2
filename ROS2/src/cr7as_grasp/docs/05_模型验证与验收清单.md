# 05：模型验证与验收清单

此清单区分“能运行”与“可安全执行”。未通过的项必须保持执行禁用。

## A. 模型与 Gazebo（当前阶段）

- [ ] `ros2 launch cr7as_grasp display.launch.py` 能启动 RViz2；
- [ ] RViz Fixed Frame 为 `base_link`，RobotModel 与 TF 完整显示；
- [ ] `ros2 launch cr7as_grasp gazebo_control.launch.py` 能生成机器人；
- [ ] `ros2 control list_controllers -c /controller_manager` 显示 `joint_state_broadcaster` 和 `arm_controller` 为 `active`；
- [ ] `j1..j6` 的单点轨迹可在 Gazebo 执行；
- [ ] `base_link -> ... -> grasp_tcp` TF 链连续；
- [ ] 记录 Gazebo 版本、ROS 2 Humble 版本与测试日期。

## B. 视觉和 P3.1（当前阶段）

- [ ] `/vision/detected_pixel` 可随红色测试物体连续变化；
- [ ] `/vision/object_pose_base` 的 `header.frame_id` 为 `base_link`；
- [ ] `/vision/object_pose_base` 位置单位确认是米；
- [ ] `/vision_guided_motion/pregrasp_pose`、`grasp_pose`、`lift_pose` 连续且位于预期工作空间；
- [ ] `/vision_guided_motion/plan_pregrasp` 只发布 `/display_planned_path`，不执行任何控制器动作；
- [ ] P3.1 的抓取姿态与 `grasp_tcp` 接近方向一致。

## C. 进入 P3.2 前（仿真执行）

- [ ] 在 Planning Scene 中加入桌面碰撞体；
- [ ] 在 Planning Scene 中加入目标物体碰撞体；
- [ ] 设定预抓取、下探和抬升的最小安全距离；
- [ ] 验证规划失败时不会发送轨迹；
- [ ] 验证取消、节点退出和控制器故障时的回退行为；
- [ ] 明确 P3.2 仅允许 Gazebo 执行。

## D. 实机前置项（全部完成前禁止执行）

- [ ] 厂家/现场确认 CR7AS 可使用 V4 CR7 的 ROS 2 控制器接口；
- [ ] `j1..j6` 与 `joint1..joint6` 一一对应已在实机零位和单关节低速测试中确认；
- [ ] 不从官方 CR7 URDF 采纳质量、惯性或惯量；本 CR7AS 模型参数来源已记录；
- [ ] `l6/flange -> grasp_tcp` 已测量、保存并在实机复核；
- [ ] 控制器 Tool ID 已创建并与 ROS `grasp_tcp` 完成一致性验证；
- [ ] 夹爪 IO 通道、有效电平、异常安全状态已确认；
- [ ] payload 与重心完成控制器标定；
- [ ] 使用 V4 `InverseKin` 检查每个目标 TCP；
- [ ] 使用 `CheckOddMovJ` / `CheckOddMovL` 对将执行的相邻轨迹段做控制器检查；
- [ ] 先以 `allow_execute: false` 完成全部只检查测试；
- [ ] 首次执行限制在低速、空载、单步、人员在场和可急停条件下。

## 通过准则

- **仿真通过** 不等于 **实机通过**；
- **MoveIt 规划成功** 不等于 **控制器 IK 可达**；
- **控制器 IK 可达** 不等于 **运动过程无碰撞/无奇异/夹爪安全**；
- 只有 D 项完整通过并由操作者明确允许，才能把实机执行开关从 `false` 改为 `true`。
