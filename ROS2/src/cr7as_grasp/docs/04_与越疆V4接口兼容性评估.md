# 04：与越疆 V4 接口兼容性评估

## 结论

本地 V4 SDK (`DOBOT_6Axis_ROS2_V4-main`) 显式提供 `cr7`，未单独提供 `cr7as` 包。根据本项目确认，CR7AS 相较 CR7 增加皮肤检测；皮肤检测不参与当前仿真。因此可将 V4 的 CR7 驱动/控制器接口作为 CR7AS 后续实机接入参考，**但仍必须经过现场验证后才允许执行**。

## 已确认映射

| 项目 | 本项目 CR7AS | 官方 V4 CR7 | 结论 |
|---|---|---|---|
| 六轴运动学基础 | CR7AS | CR7 | 仿真阶段按 CR7 对照；皮肤检测不处理。 |
| 关节 1–6 | `j1..j6` | `joint1..joint6` | 一一对应。 |
| 硬件控制器名 | CR7AS 采用 CR7 对照 | `cr7_group_controller` | 保持一致；仅供后续硬件桥接使用。 |
| 官方模型末端 | `grasp_tcp` | `Link6` | 官方无夹爪/TCP，本项目必须保留自己的工具链。 |
| 质量/惯性/惯量 | 本包 CR7AS URDF | 官方 CR7 URDF | 官方值不准确，**不采纳**；保留本包值。 |
| 皮肤检测 | 具备 | CR7 基准未建模 | 当前仿真不处理。 |

## V4 可复用的接口能力

未来硬件桥接可参考：

- Bringup：`dobot_bringup_v4`，通过 `IP_address` 与 `DOBOT_TYPE=cr7` 选择控制器；
- 控制器标定 DH 的目标 IK：`InverseKin.srv`；
- 运动与状态：`EnableRobot`、`RobotMode`、`GetPose`、`GetAngle`、`MovJ`、`MovL`、`ServoJ`、`Stop`、`ClearError`；
- 轨迹动作：`/cr7_group_controller/follow_joint_trajectory`；
- 运动可达性预检查：`CheckOddMovJ.srv`、`CheckOddMovL.srv`；
- 末端接口候选：`ToolDO.srv`、`ToolDOInstant.srv`、`SetTool.srv`、`SetToolPower.srv`、`SetTool485.srv`。

## 不可直接复用的部分

1. 官方 CR7 URDF 末端仅到第六轴，缺少夹爪与 `grasp_tcp`；
2. 官方 CR7 URDF 的质量、惯性、惯量不准确，不能用于本项目 Gazebo；
3. 本项目内部关节名是 `j1..j6`，官方接口为 `joint1..joint6`，必须经显式映射后才能跨接口传递；
4. 当前仿真控制器名为 `arm_controller`，不等于实机 `cr7_group_controller`；
5. TCP、Tool ID、夹爪 IO、电平、负载和重心仍未确认。

## 后续硬件接入安全链

```text
P2 目标位姿
  -> MoveIt 碰撞规划
  -> V4 InverseKin（控制器标定 DH）
  -> CheckOddMovJ / CheckOddMovL（控制器运动过程检查）
  -> 用户明确确认 + 低速限制
  -> /cr7_group_controller/follow_joint_trajectory
  -> ServoJ
```

当前 P3.1 只停在第一步：MoveIt 仅规划。任何一步未完成均不得执行。
